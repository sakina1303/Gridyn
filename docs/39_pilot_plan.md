# Advisory pilot path

| Phase | Work | Exit evidence |
|---|---|---|
| 1 Synthetic | Reproducible campus archetypes, stress cases, independent validation | Mathematical and simulation gates pass |
| 2 Historical data | Consent, data inventory, meter and bill reconciliation, tariff version, asset constraints | Readiness report and retrospective errors; no operational claim |
| 3 Shadow mode | Daily recommendations logged but not executed; compare forecast and possible deliverability with actual conditions | Prospective calibration and operator review |
| 4 Operator feedback | Interviews, action feasibility, comfort/service exceptions, reasons for override | Revised constraints and usability evidence |
| 5 Controlled deployment (optional, separate project) | Partner-led safety/engineering review, permissions, manual approval, rollback, monitoring | Explicit operating protocol; student prototype never directly controls assets |

Minimum partner data: 15 minute import meter if available, PV output, asset ratings, battery SOC/power if present, EV/pump/HVAC schedules, critical load definition, applicable tariff, consent and retention terms. Start with de-identified data and manual CSV exchange. Make no pilot claim before a partner exists. Network benefit claims additionally need feeder/transformer topology, ratings and relevant measurements.
