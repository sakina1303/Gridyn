# Security and privacy boundary

MVP uses synthetic data and a local single-user environment. Collect no personal EV driver IDs or individual occupancy records; sessions use pseudonymous event IDs and aggregate charging demand. Meter IDs and facility location can be sensitive operational metadata, so reports show only the granularity needed. Uploaded CSVs are parsed with size/type limits and stored outside source control; reject executable content and formula injection in exports. No live credentials or utility APIs are required.

For a real-data pilot, obtain written site authorization and a data inventory defining purpose, permitted users, retention/deletion date, and whether data may leave the site. Minimize to interval energy and asset constraints. Pseudonymize EV sessions, aggregate occupancy, encrypt transfer/storage, control access by named role, audit dataset/report access, and delete raw data on request/retention expiry. Separate raw, normalized and published artifacts; redact meter IDs, exact facility layout and sensitive schedules in public demos. Log IDs and diagnostics rather than raw traces. A local prototype's simple account model is not a production security claim. Physical control is prohibited.
