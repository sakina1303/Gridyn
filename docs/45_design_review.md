# Design consistency review

Status: planning review, 22 October 2026. All requested sources [15–44](44_final_architecture_decision.md) exist and were inspected. The approved [44](44_final_architecture_decision.md) governs product scope. Earlier numbered 45/46 files were preserved as `docs/superseded_45_implementation_plan.md` and `docs/superseded_46_design_review.md`; this document and [46](46_canonical_model.md) replace them for the new sequence. “Conflict” includes an underspecified choice that would cause modules to diverge.

| Topic | Current definitions and location | Conflict / ambiguity | Canonical resolution and reason | Earlier documents to align |
|---|---|---|---|---|
| Resolution | [22](22_flexibility_model.md) permits 15/30/60 min; [26](26_campus_simulation.md) demos 15 min; [24](24_data_readiness.md) warns hourly hides peaks | A coarse input might be mistaken for 15 min truth | Truth grid is 15 min for experiments; observations may be aggregated to 30/60 min. Optimization may run at selected compatible resolution, and claims cannot exceed observed resolution. This makes ablations fair. | 22, 24, 26, 31, 33 |
| Time zone | [22](22_flexibility_model.md), [24](24_data_readiness.md), [35](35_data_model.md) say UTC storage with IANA site zone | Interval convention and DST not explicit everywhere | Store half-open UTC intervals `[start,end)`; use IANA zone for display/tariff calendar; reject ambiguous/nonexistent local timestamps unless offset supplied. India demo uses `Asia/Kolkata`. | 22, 24, 35, 36 |
| Units | [22](22_flexibility_model.md) uses kW/kWh; [24](24_data_readiness.md) allows meter kWh/interval | Aggregation conversion could differ | Internal average kW per interval and kWh via `kW×Δh`; tariff INR/kWh, demand charge INR/kW per defined billing peak. Keep original input unit and conversion audit. | 22, 24, 35, 36, 40 |
| Asset definitions | [22](22_flexibility_model.md) separates fixed/critical/flexible; [26](26_campus_simulation.md) lists fixed/critical/HVAC etc. | Critical could be counted twice in fixed demand | `L_crit`, `L_fixed_noncritical`, and each flexible asset are disjoint. HVAC has fixed and controllable portions explicitly. | 22, 26, 35 |
| Sign conventions | [22](22_flexibility_model.md) positive grid import, down response lowers import | PV/export signs in API not fixed | All physical flows `i,e,g,u,c,d,L≥0`; net grid `P=i−e`. Up response raises `P`; down response lowers `P`. | 22, 36, 37 |
| Battery/SOC | [22](22_flexibility_model.md) defines kWh state, percentage display; [26](26_campus_simulation.md) 20–90% example | Nominal versus usable capacity and terminal SOC unresolved | `E_t` stored in kWh, `[E_min,E_max]` derived from configured nominal capacity and SOC limits. Equal initial SOC across paired runs; enforce `E_T≥E_0` in comparison horizon unless explicit carryover model. This prevents artificial end-of-horizon savings. | 22, 26, 27, 30 |
| Efficiency/rates | [22](22_flexibility_model.md) separate charge/discharge efficiencies, 50 kW demo rates | Whether rates are AC-side is unstated | All `c,d` are AC-bus kW; SOC equation uses `ηc` and `ηd`; inverter losses are represented there. | 22, 26, 27 |
| Tariffs | [24](24_data_readiness.md) requires tariff only for cost claim; [26](26_campus_simulation.md) synthetic tariff | Demo savings could read as actual Indian bill saving | Synthetic tariff is labeled scenario; cost claim requires versioned applicable order, category, demand/export rules. Physical flexibility is tariff independent. | 24, 26, 30, 40, 43 |
| Forecast/optimization horizons | [27](27_optimization_model.md), [28](28_forecasting_architecture.md) allow 24–48 h | Different horizons make comparisons unfair | First benchmark uses 24 h forecast and 24 h schedule plus explicit recovery/terminal horizon; 48 h is later sensitivity. Same horizon for baselines. | 27, 28, 31 |
| Uncertainty | [23](23_uncertainty_framework.md) uses scenario fraction; [22](22_flexibility_model.md) calls it reliable | Could imply calibrated real probability from synthetic scenarios | Report tested deliverability fraction, N, scenario source, and interval; call “simulation-conditional reliable” only at stated threshold. If no calibrated set, `unknown`. | 22, 23, 36, 37, 40 |
| Baseline | [22](22_flexibility_model.md) says no-new-action; [26](26_campus_simulation.md) “no flexibility” | No-action must still serve EV/pump/comfort | Freeze valid service schedules, battery idle, same truth and initial SOC. Rule and all optimizers meet identical obligations. Perfect-information case is an upper bound, not a deployable baseline. | 22, 26, 30, 31 |
| Flexibility | [22](22_flexibility_model.md) per-time maxima and sustained-window test | Per-time maxima cannot be composed into a schedule | Authoritative output is a *joint feasible* `(start,duration,direction,q)` response with recovery; time-slice envelope is a visualization, never additive. | 22, 37, 40 |
| Critical load | [22](22_flexibility_model.md) and [27](27_optimization_model.md) hard requirement | Diagnostic slack could leak into recommendation | Critical demand always hard; diagnostic service slack may be used only for noncritical infeasibility analysis and must never yield recommendation. | 27, 29, 41 |
| Scenarios/experiments | [30](30_scenario_engine.md) scenario config; [31](31_experimental_protocol.md) experiment comparison | “Scenario” and “experiment” could be conflated | Scenario = immutable site/asset/weather/tariff/observation config; experiment = protocol over paired scenario/run set with hypothesis, seeds and metrics. | 30, 31, 35, 36 |
| API/database/UI | [35](35_data_model.md) `FlexibilityAssessment`, [36](36_api_spec.md) uses `/flexibility-assessments`, [37](37_ui_spec.md) “Flexibility Assessment” | Stable IDs and terminology need one mapping | Preserve these names; `ResponseEnvelope` is a typed result inside an assessment, not another database entity/API resource. | 35, 36, 37 |
| Metrics | [40](40_success_metrics.md) peak, cycles, cost; [22](22_flexibility_model.md) defines PV utilization | Cycle and reliability denominators could vary | Peak `max i_t` for study horizon; import/export energy integrated; equivalent cycles = discharged kWh/usable battery kWh; success fraction = valid responses/tested cases. Include eligible denominator and units. | 22, 40 |
| Tool scope | [33](33_mvp_scope.md) says CSV+UI; [34](34_system_architecture.md) proposes PostgreSQL/Docker | Infrastructure can delay research core | Modular Python monolith and local file/SQLite first; PostgreSQL migration and Docker after scientific gates. React UI after stable numerical core. | 33, 34, 44 |

All requested documents **15–44** exist. The original master build brief also proposed documents **01–14**, and those files are absent from this repository; their topics overlap later designs but no missing research was silently treated as complete. Unresolved *evidence* decisions: real operator demand, pilot dataset access, applicable tariff, solver installation/performance, and prior-art depth. These do not prevent a simulation-first MVP if kept as explicit gates; they do prevent claims of real-world effectiveness or proven novelty. The canonical contracts are in [46](46_canonical_model.md).
