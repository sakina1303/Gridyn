# Small optimizer implementation contract

First solve an LP fixture, then a 24 h MILP at 15 min resolution (96 intervals) with Pyomo + HiGHS **provisionally**; verify solver availability, version, license and runtime at implementation setup. [Pyomo solver interface](https://pyomo.readthedocs.io/en/latest/api/pyomo.contrib.solver.solvers.highs.Highs.html). OR-Tools MathOpt is fallback if installation/performance is poor. [OR-Tools](https://developers.google.com/optimization/math_opt). Do not implement a hand-written heuristic and call it an optimizer.

Variables are [27](27_optimization_model.md): `i,e,u,c,d,E`, EV charging power, pump binary/on power, optionally bounded HVAC flexible power, grid/battery direction binaries, peak `K`, and only diagnostic noncritical service slack. Apply [46](46_canonical_model.md) balance/SOC/limits, service windows, terminal reserve, ramp/minimum run if configured. Default objective profile is tariff cost plus separately configured peak/curtailment/throughput penalties; weights carry units and are saved. Alternative `peak`/`solar-use` profiles are separate named runs. Critical load and physical constraints are hard, always.

Before solving, validate obvious infeasibility: SOC range, impossible EV due energy, pump service/window, grid and PV bounds, tariff/objective coefficients and horizon. Solver options: fixed thread count where supported, time limit (initial 30 s research fixture), relative MIP gap target (initial 1%), fixed seed where supported, all recorded. A feasible incumbent after timeout may be reported as `suboptimal_feasible` with gap; it is never called optimal. No incumbent, infeasible, unbounded, numerical error, or failed independent validation yields no recommendation. Diagnostic reruns may relax **noncritical** obligations and name the minimum shortfall; critical demand cannot be relaxed.

Log config/dataset hashes, solver and package versions, status/termination, objective components, bound/gap, runtime, variable schedule and maximum residuals. Warm starts are optional only after a working deterministic solve; they must not change outcome semantics. Recompute cost, balance, SOC, service and direction constraints in independent code with stated absolute/relative tolerance before persisting a validated run.
